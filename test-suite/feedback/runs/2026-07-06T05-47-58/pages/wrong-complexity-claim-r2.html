    if not nums:
        return []
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):

    return []

Thinking & Logic

Your approach was brute force: for each index i, scan j>i until you find a pair summing to target and return immediately. This is logically valid, but the reasoning broke down at the complexity step: the inner scan is not “part of processing each element” in a way that stays linear—across all i it sums to ~n(n-1)/2 checks, which is quadratic and incompatible with n up to 1e5.

Code Assessment

The final code matches the answer key’s brute_force solution (nested loops, O(n^2) time, O(1) space). Compared to the canonical optimal solution, it misses the key technique: a single-pass hash map of seen values to index, checking `target - nums[i]` before inserting `nums[i]`. That optimal pattern reduces runtime from O(n^2) to O(n) and is what the constraints require; your solution likely failed the hidden performance case for that reason.
