Thinking & Logic

You used a brute-force pair scan: for each index i, you scanned subsequent indices j to find nums[i] + nums[j] == target. That reasoning is sound for correctness on small/medium inputs and guarantees distinct indices, but it ignores the explicit constraint that an O(n^2) scan will time out at n up to 1e5. The complexity analysis also missed that the inner scan is repeated for each i, so total work grows quadratically.

Code Assessment

Your final code matches the answer key’s brute_force approach (nested loops, O(n^2) time, O(1) space). The canonical optimal solution you missed is the single-pass hash map (value -> index) that checks for the complement before inserting; that achieves O(n) time and is robust to large hidden tests. As written, the code is likely failing the largest hidden test due to runtime, not due to incorrect output logic.
