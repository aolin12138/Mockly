    if not nums:
        return []
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:

    return []

Thinking & Logic

You implemented a brute-force nested scan: for each index i, you search j>i until you find nums[i] + nums[j] == target and return the pair. That approach is logically correct for finding a pair, and your j loop starting at i+1 prevents reusing the same element. However, it performs ~n(n-1)/2 checks in the worst case, which conflicts with the constraint note that O(n^2) will time out on the largest hidden case.

Code Assessment

Your final code matches the answer key’s brute_force approach (nested loops, O(n^2) time, O(1) space). The canonical optimal solution for this prompt is a single pass with a hash map (seen value -> index) where you compute complement = target - nums[i], check if it’s already seen, and return immediately; this achieves O(n) time and passes large hidden performance tests. Your solution did not adopt that pattern, and the incorrect O(n) complexity claim suggests a gap in runtime reasoning.
