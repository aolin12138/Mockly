def solve(nums, target):
    if not nums:
        return []
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return [i, j]
    return []

Thinking & Logic

The implemented approach checks every pair (i, j) with i < j and returns as soon as it finds a pair summing to target. While this is logically straightforward and correct for many cases, it scales poorly because it performs up to ~n(n-1)/2 checks. The interview discussion also mischaracterized this as O(n), which conflicts with both the code structure and the stated constraints warning about timeouts.

Code Assessment

Your final code matches the answer key's brute-force solution (nested loops, O(n^2) time, O(1) space). The canonical optimal solution you missed is the single-pass hash map (value->index) approach: for each number x at index i, check whether target-x is already in the map; if so return those indices, otherwise store x. That technique reduces runtime to O(n) and is the expected solution under the given constraints; your current code cannot guarantee passing the largest hidden case.
